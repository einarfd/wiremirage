Connect an agent

WireMirage speaks MCP over streamable HTTP, so an MCP-capable agent (Claude Code, Claude Desktop, Cursor, …) can drive it with no install — just this endpoint and a token.

1. The endpoint

{{ mcp_url }}
  • Transport: streamable HTTP.
  • Auth: bearer token in the Authorization header.
  • Mock traffic from your system-under-test hits your routes directly and needs no token — only this control endpoint does.

2. Get a token

Mint a dedicated token for the agent on the API tokens page — it's shown once, so copy it then. A non-admin token confines the agent to routes it owns; an admin token can see everything.

3. Add it to your agent

Claude Code

claude mcp add --transport http wiremirage {{ mcp_url }} \
  --header "Authorization: Bearer YOUR_TOKEN"

Config-file clients (Cursor, VS Code, …)

Add to the client's MCP config (e.g. mcp.json):

{
  "mcpServers": {
    "wiremirage": {
      "type": "http",
      "url": "{{ mcp_url }}",
      "headers": { "Authorization": "Bearer YOUR_TOKEN" }
    }
  }
}

Claude Desktop

Settings → Connectors → Add custom connector, then paste the endpoint above. Provide the bearer token when prompted.

Once connected, the agent can discover the surface itself with the summarize_workspace and get_capabilities tools — it doesn't need to be told the handler API up front.

Troubleshooting

  • An opaque "authorization failed" on connect (with a valid token) usually means the host's Host allowlist doesn't include this domain — an operator sets WM_TRUSTED_PROXY to the public hostname.
  • Tools returning 403 mean the token's user isn't owner-or-admin for that route or group.
